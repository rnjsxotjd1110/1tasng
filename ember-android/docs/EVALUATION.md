# Ember 사용성 평가 기록

앱을 처음 보는 평가 에이전트 4명(역할 고정)이 매 차수 **새로** 투입되어, 스크린샷과 사용 흐름 안내만 보고(코드 열람 금지) 실제 출시된 상위권 앱을 90점대 기준으로 엄격하게 채점했습니다. 같은 채점표(9개 항목, 100점)를 매번 사용했습니다.

| 역할 | 1차 | 2차 | 3차 | 4차 | 5차 | 6차 | 7차 | 8차(최종) |
|---|---|---|---|---|---|---|---|---|
| Godot 입문 개발자 | 67 | 70 | 73 | 76 | 73 | 70 | 77 | **79** |
| 시니어 모바일 UX 디자이너 | 61 | 68 | 70 | 71 | 78 | 69 | 74 | **78** |
| 영어권 스타트업 PM | 66 | 68 | 71 | 73 | 70 | 69 | 72 | **72** |
| QA 리드·접근성 전문가 | 66 | 71 | 79 | 79 | 74 | 79 | 80 | **80** |
| **평균** | **65.00** | 69.25 | 73.25 | 74.75 | 73.75 | 71.75 | 75.75 | **77.25** |

- 목표: 1차 평균 대비 +10점(75점 이상) → 7차 75.75점에서 달성, 최종 배포본(8차) 77.25점(+12.25)으로 재확인.
- 6차 하락 원인: 오류 카드의 버튼 글자 잘림 회귀. 7차에서 수정하고 이후 평가 전 직접 화면 검수를 추가했습니다.
- 8차 이후 반영한 작은 수정 3건(섹션 '다시 쓰기' 라벨, 영어 홈 하단 여백, 'CLAUDE.md 저장' 라벨)은 재채점하지 않았습니다.

## 차수별 주요 개선

| 차수 | 반영 내용 |
|---|---|
| 2차 | 한국어 어절 줄바꿈, 조사·해요체 통일, 버튼 대비 4.5:1, 키 없는 체험 모드, 행동별 예상 비용, 빠른 아이디어 받기, 질문 진행 '질문 n / 약 N' |
| 3차 | 핵심 버튼 잘림 해결, 원화 통일, 질문 대기 중 내 답·다음 질문 자리 표시, 아이디어 비교, CLAUDE.md 내보내기, 앱 설계서에 사용자 스토리·수용 기준 |
| 4차 | 오류 시 고른 답 유지, 월 예산 한도, 아이디어에 참고 작품·위험·검증 방법, 이어서 하기 우선 배치 |
| 5차 | 가로 비교표, 작성 중 섹션 계획 목록, 재방문 홈 압축, 앱 기획서 예시 |
| 6차 | A/B/C 선택지 배지, 온보딩 그림을 실제 화면 축소판으로, 모든 시트 닫기 버튼, 보관함 탭·필터 정리 |
| 7차 | 오류 카드 회귀 수정, 넘기기 시트에 프롬프트 미리 보기 상단 배치, 설계서 표·제목 정리 |
| 8차 | 설계서 직접 편집(무료 새 버전), 섹션만 다시 쓰기, API 선결제 안내 |

## 남은 과제(최종 평가에서 반복 지적)

- API 키·크레딧 선결제라는 진입 장벽(앱 구조상 남음, 체험 모드로 완화)
- 질문마다 Claude 응답을 기다리는 왕복 대기(묶음 질문·미리 받기 미구현)
- 직접 편집기가 원문 Markdown 한 덩어리(섹션 단위 편집·미리 보기 미구현)
- 버전 비교(diff), 백그라운드 완료 알림, Notion·GitHub 이슈 내보내기 미구현
